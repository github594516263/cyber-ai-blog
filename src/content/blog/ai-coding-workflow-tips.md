## 告别机械搬砖：AI 在日常开发里到底能干啥？

身边不少同事讨论 AI 时，要么觉得它无所不能，要么试了一次觉得它写的代码跑不通就弃用了。作为一个每天都在写前端页面和后端接口的全栈开发，我最大的体会是：**不要让 AI 替你做架构猜想，而是给它明确的上下文和规则，让它帮你干最繁琐的体力活。**

下面分享几个我每天都在用的真实提效场景。

---

## 场景一：根据后端接口秒生前端代码與表单配置

在开发中后台系统时，最耗时间的往往是对着后端的字段文档，手敲几十个表格列（Columns）、搜索项（Search Items）和 TypeScript 接口定义。

现在的做法是：
1. 把项目里封装好的一个标准页面模板（或者组件编写规范 Skill）丢给 AI；
2. 粘贴后端接口返回的 JSON 示例或 Swagger 文档；
3. 让 AI 直接按项目规范输出完整的 Vue 页面和 API 调用文件。

原本需要半小时对齐字段的活，现在 **2 分钟生成 + 3 分钟微调检查** 就能联调完毕。

---

## 场景二：复杂 SQL 查询与数据转换脚本

遇到多表联查、分组统计或者需要把一批旧数据清洗成新格式时，直接把表结构貼给 AI：

```sql
-- 让 AI 辅助编写并优化带窗口函数的统计查询
SELECT 
  department_id,
  employee_name,
  salary,
  RANK() OVER (PARTITION BY department_id ORDER BY salary DESC) as dept_rank
FROM employees
WHERE status = 'ACTIVE';
```

写完后再顺手问一句：*“这条 SQL 在数据量上百万时有哪些索引优化建议？”*，往往能提前避开不少慢查询的坑。

---

## 场景三：总结我的「AI 结对三原则」

1. **给足上下文（Context）**：提问时带上相关文件、报错完整日志和依赖版本，少说“帮我写个登录”，多说“基于现有的 `request.ts` 封装写一个带 Token 刷新的登录接口”。
2. **小步快跑**：每次只让 AI 修改一个独立功能或组件，改完立刻在本地跑起来验证。
3. **沉淀自己的模版库**：把平时常用的组件范式、代码规范整理成 Markdown 文档，需要时直接引用，越用越顺手。
